# 订单系统重新设计 - 设计规格文档

> **创建日期**: 2026-04-07
> **状态**: 待实施

## 一、需求概述

### 业务背景

户外广告订单系统中，一个订单（店铺）通常包含多个广告项目（KT板、软膜灯箱、发光字等），每个广告项目又有多个面（正面、左侧、右侧等），每个面需要上传现场照片并填写尺寸、材质等属性。

### 核心需求

1. **订单基本信息可配置** - 不同业务场景需要的字段不同
2. **广告类型可配置** - KT板、软膜灯箱、发光字等
3. **面配置** - 正面、左侧、右侧、顶部等
4. **属性模板可配置** - 不同广告类型/面需要的属性不同
5. **每个面必须上传图片** - 固定业务规则

## 二、数据模型设计

### 2.1 新增模型

#### Face (面配置)

```javascript
// backend/src/models/Face.js
{
  id: INTEGER PRIMARY KEY AUTO_INCREMENT,
  name: STRING(50) NOT NULL COMMENT '面名称',
  code: STRING(20) COMMENT '面代码',
  sort_order: INTEGER DEFAULT 0 COMMENT '排序',
  status: TINYINT DEFAULT 1 COMMENT '状态：1启用 0禁用'
}
```

#### AttributeTemplate (属性模板)

```javascript
// backend/src/models/AttributeTemplate.js
{
  id: INTEGER PRIMARY KEY AUTO_INCREMENT,
  name: STRING(50) NOT NULL COMMENT '模板名称',
  description: STRING(200) COMMENT '模板说明',
  sort_order: INTEGER DEFAULT 0 COMMENT '排序',
  status: TINYINT DEFAULT 1 COMMENT '状态：1启用 0禁用'
}
```

#### AttributeField (模板属性字段)

```javascript
// backend/src/models/AttributeField.js
{
  id: INTEGER PRIMARY KEY AUTO_INCREMENT,
  template_id: INTEGER NOT NULL COMMENT '所属模板ID',
  field_name: STRING(50) NOT NULL COMMENT '属性名称',
  field_key: STRING(50) NOT NULL COMMENT '属性标识',
  field_type: ENUM('text', 'number', 'select', 'radio', 'checkbox', 'textarea', 'date') COMMENT '字段类型',
  options: JSON COMMENT '选项配置',
  unit: STRING(20) COMMENT '单位',
  is_required: TINYINT DEFAULT 0 COMMENT '是否必填',
  default_value: STRING(200) COMMENT '默认值',
  placeholder: STRING(100) COMMENT '占位文本',
  sort_order: INTEGER DEFAULT 0 COMMENT '排序',
  status: TINYINT DEFAULT 1 COMMENT '状态'
}
```

## 三、API 设计

### 3.1 面配置 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/faces` | 获取面列表 |
| GET | `/api/v1/faces/:id` | 获取单个面 |
| POST | `/api/v1/faces` | 创建面 |
| PUT | `/api/v1/faces/:id` | 更新面 |
| DELETE | `/api/v1/faces/:id` | 删除面 |

### 3.2 属性模板 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/attribute-templates` | 获取模板列表（含字段） |
| GET | `/api/v1/attribute-templates/:id` | 获取单个模板详情 |
| POST | `/api/v1/attribute-templates` | 创建模板 |
| PUT | `/api/v1/attribute-templates/:id` | 更新模板 |
| DELETE | `/api/v1/attribute-templates/:id` | 删除模板 |
| POST | `/api/v1/attribute-templates/:id/fields` | 添加属性字段 |
| PUT | `/api/v1/attribute-fields/:id` | 更新属性字段 |
| DELETE | `/api/v1/attribute-fields/:id` | 删除属性字段 |

### 3.3 广告类型 API (扩展)

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/ad-types/:id/config` | 获取广告类型的完整配置（含面和属性模板） |

### 3.4 订单 API (调整)

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/orders` | 创建订单（含广告项目） |
| GET | `/api/v1/orders/:id` | 获取订单详情（含广告项目） |

## 五、技术实现要点

### 5.1 图片上传

- 每个面的图片为必填项
- 支持多图上传
- 支持拖拽上传
- 图片压缩（前端）
- 存储路径: `uploads/YYYY-MM-DD/filename.ext`

### 5.2 动态表单渲染

- 根据属性模板动态渲染表单控件
- 支持字段类型：文本、数字、下拉、单选、复选、多行文本、日期
- 支持必填验证
- 支持单位显示

### 5.3 数据存储

- 订单基本信息存储在 `orders` 表
- 广告项目存储在 `order_ad_items` 表
- 每个项目的面数据以 JSON 形式存储在 `faces` 字段
- 图片 URL 存储在 `faces[].images` 数组中

## 八、验收标准

1. 系统设置中可管理面配置（CRUD）
2. 系统设置中可管理属性模板及属性字段（CRUD）
3. 广告类型可配置启用的面及对应的属性模板
4. 新建订单页面采用分步骤向导
5. 基本信息页支持动态表单字段
6. 广告项目页可添加多个项目，每个项目根据配置显示面和属性
7. 每个面必须上传图片
8. 确认页可预览所有信息
9. 提交后数据正确保存到数据库
